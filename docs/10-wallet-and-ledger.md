# WALLET AND LEDGER

## Principle

The wallet is an accounting projection backed by an immutable transaction ledger. Never treat a client-visible balance as authoritative input.

## Currency

Internal wallet currency is USD only.

## Balances

Maintain available and reserved amounts. Available funds can be spent or withdrawn. Reserved funds are committed to an in-flight operation and cannot be spent again.

Invariant: available + reserved must equal the wallet's represented outstanding balance according to the ledger model.

## Ledger entries

Each entry has a unique ID, wallet/user, type, direction, exact amount, currency, source reference, idempotency key, timestamp and metadata. Corrections use compensating transactions.

## Entry fee

An entry fee is a USD debit tied to a registration and competition. It must not be possible to debit a wallet without a valid business reference.

## Winnings

Winnings are USD credits generated by an authorized settlement. The settlement result and wallet transaction must reference each other.

## Withdrawal reservation

When a withdrawal is accepted, the requested amount moves from available to reserved through controlled ledger/state logic. Reservation prevents double spending while the external payout is pending.

## Reversals

Failed/cancelled withdrawals release the reservation. A completed payout consumes the reserved amount. The exact state transition must be recorded.

## Administrative adjustments

Admins cannot simply edit balance numbers. They create a controlled adjustment transaction with reason, actor and audit record.

## Idempotency

Every operation that may be retried must have a unique idempotency/reference key. Repeating the same operation returns the existing outcome rather than changing the balance again.

## Precision

Use integer minor units for USD where practical. Conversion calculations must use exact decimal arithmetic and an explicit rounding policy. Never use binary floating point for authoritative money calculations.
